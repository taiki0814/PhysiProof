# 走行傾向とプロフィール設定

## 利用者向け

- ダッシュボードの「走行傾向」から、曜日×2時間帯の表を表示する。領域マップとは別メニュー。
- 「自分の傾向」は本人の完了済み走行回数・距離。「みんなの傾向」は協力者の走行開始傾向であり、地域の人出・道路の混雑・現在の安全性を表すものではない。
- 直近4週間／8週間を選べる。日本時間の今日0時を終端とする28日／56日間で、今日の走行は翌日以降に反映する。
- 開始日時で曜日・時間帯を分類する。距離・時間がともに正で、前日までに終了した走行が対象。個人・チーム活動、領域取得のない走行も含む。日付のない旧推定総距離から時間帯を捏造しない。
- 協力設定は初期オフ。「有効化して保存した日時以降に開始した走行」だけ全体集計の対象。繰り返しオンを保存しても同意日時は変わらない。オフで全協力分を対象外とし、再度オンにした場合は新たな同意日時から対象にする。
- 全体集計は各区分の異なる利用者数を用いる。同じ人が繰り返し走っても人数は増えない。5人未満は0人でも「データ不足」、5〜9人／10〜19人／20人以上は3段階の色だけで、正確な人数や全体距離・合計回数は公開しない。
- 地域・位置・経路・年齢・性別・身体情報による絞り込みは設けない。プロフィール地図の公開範囲やフレンド関係とも独立した設定。
- コーチと未来予測のメニュー・画面への入口を撤去した。身長、現在／目標体重、任意の性別は「プロフィール設定 → 身体情報」で入力可能。空欄保存は値を消去する。他ユーザーのプロフィールや走行傾向へは公開しない。既存管理者の管理用閲覧権限は変更しない。

## API / 永続化

すべて通常のパスワード発行セッションが必要。本人IDを入力させず認証から確定し、`Cache-Control: private, no-store`。端末の永続キャッシュや新しいGPSデータは追加しない。

| Method | Endpoint | 用途 |
| --- | --- | --- |
| GET | `/api/running/trends?scope=community&weeks=4` | 前日までの匿名段階集計と本人の協力設定 |
| GET | `/api/running/trends?scope=personal&weeks=8` | 本人だけの走行回数・距離 |
| PUT | `/api/running/trends/preferences` | `{ "sharing": true/false }` を本人に保存 |
| PUT | `/api/users/me/vitals` | 身体情報4項目を本人に保存。`null`で消去 |

- Zodの共有スキーマでクエリー・入力・出力を検証。84区分の重複や全体集計への正確な数値混入を拒否する。
- マイグレーション0038は同意フラグ・同意日時・完了走行の開始日時索引・新メニュー既定値だけを追加する。既存走行・領域・対戦得点・身体情報を移し替えない。
- 身体情報の専用APIは4項目以外を更新しない。表示名・年齢・地図公開範囲・カロリー目標を古いフォーム値で上書きしない。
- PC・スマホ・管理画面の表示設定は共通のメニュー定義を利用する。古いコーチ／予測のURLはホームに戻り、旧表示設定でも復活しない。バックエンド互換APIと既存データは削除しない。
- 集計は要求時のD1 SQL。生データ・正確な全体人数をブラウザーへ渡さず、オプトアウトは次の集計から反映する。開きっぱなしの画面は再表示・フォーカス・期間変更で更新される。統計的な匿名化の完全保証ではないため、地域別・少人数別フィルターは追加しない。

## 検証

`runningTrends.integration.test.ts` は本番／開発DBに接続せず、全マイグレーションを適用したメモリー内SQLiteと実セッションで検証する。共有・画面テストを含む全957件のテスト、root/frontend型検査、本番向けビルドを実行。

実ローカル画面では認証済みユーザーの傾向表示・切替を確認するだけとし、健康情報や同意をテストのために変更しない。`/qa/running-trends.html` はVite専用の架空データ画面で、すべてのAPI呼び出しをメモリー内で処理し、保存・不足・エラー・スマホ表示を確認する。本番ビルドには含めない。
