# ユニフォーム工房・素材追加ガイド

## 編集の流れ

ユニフォームタブで個人用／チーム用を選び、服本体、正面と背面の柄、生地、配色、エンブレム、背面の名前・番号を組み合わせます。名前と番号の書体・高さ・サイズは別々に設定できます。正面／背面を切り替えて確認し、保存ボタンで確定します。「この面の画像を保存」は画像の書き出しであり、アプリ上の設定保存とは別です。

チーム共通デザインは現在のリーダーだけが変更できます。メンバーは自分の名前・番号のみ変更でき、他の人の設定に影響しません。ユニフォームは外見の機能です。ランニング、領域、対戦得点は変更しません。

保存済みの旧版（version 1）は旧レンダラーでそのまま表示します。「新しい工房で作る」を押すと新版（version 2）の下書きになります。名前・番号・一部配色を引き継ぎますが、旧版の柄・装飾は完全には再現しません。保存するまではDBの旧版は変わりません。従来の完成品テンプレートも引き続き選択できます。

## 管理者が追加できるもの

管理者画面のユニフォーム管理に「素材ライブラリ」を追加しています。「完成品テンプレート」とは別のカタログです。

| 素材 | 入力・編集 |
|---|---|
| 服本体 | 標準モデルをコピーし、モデル定義JSONを編集／読み込み／書き出し |
| 柄 | PNG/JPEG/SVGの取り込み、図形制作、部位分け、身頃／全面／繰り返し、配色、スケール |
| エンブレム | PNG/JPEG/SVGの取り込み、図形制作、部位分け、元の配色／ユーザー指定色 |

「下書き」は管理者だけ、「公開中」はユーザーの工房で選択可能、「非表示」は新しい選択肢から外します。既存ユニフォームが参照する公開済みバージョンは非表示後も表示可能です。公開済み画像はURLを知っていれば閲覧できるため、個人情報を含む画像は公開しないでください。

図形制作では、長方形・楕円・盾・三角形・星・線・ペン、レイヤー、取り消し・やり直しを使えます。「この下書きを素材にする」で画像と編集原稿をフォームへ反映し、その後「新バージョンとして保存」で登録します。ブラウザ下書きはアカウント・素材種類ごとに分離します。図形原稿JSONの読み込み／書き出しにも対応します。

### 柄・エンブレムの部位別カラー

管理者は「素材ライブラリ → 柄／エンブレム」から画像を読み込みます。PNG/JPEG、安全性を確認してPNGに変換したSVGのいずれも同じ操作です。新しく取り込んだ画像は色から最大6部位の候補を作り、「ユーザーが変えられる部位」に表示します。既存画像は自動変更せず、開いて部位を設定した新バージョンだけに適用します。

1. 「色で自動分け」で色数を選び、候補を作ります。これはブラウザ内の色クラスタリングであり、AIによる目・輪郭などの意味認識ではありません。外部への画像送信・新しい有料サービスはありません。
2. 部位を選んで「部位の名前」を変更します。例えば「輪郭」「左目」「右目」「背景」など、ユーザーに分かる名前にしてください。
3. 元が同じ色の別部位は「部位を追加」して「つながった範囲」で画像をタップします。離れた同色部分はそのまま残ります。つながっている同色部分は「ブラシ」で分離し、「未割り当てに戻す」で修正できます。「同じ色すべて」は画像内の同色部分をまとめて割り当てます。
4. 目印は編集用の重ね表示で、元画像には焼き込みません。「取り消し」は直近12操作に対応します。名前・範囲を確認して「新バージョンとして保存」し、公開します。

ユーザーは工房で対象素材を選び、「正面の柄／背面の柄／エンブレムの部位カラー」からそれぞれ変更します。正面と背面で同じ画像を使っても別々の配色を保存できます。「この素材の色を元画像に戻す」でその面・素材だけをリセットします。プレビューと画像書き出しには同じ着色処理を使用します。個人／チームの保存権限は従来どおりです。

- 最大16部位、部位名は30文字以内。部位マップは縦横比を維持した最大512px、1画素1バイトの索引です。細部の精度はこの解像度によるため、非常に細い線は範囲を拡大して確認してください。
- 指定した部位のみ選んだ単色で置換します。元画像・透明度・未割り当て部分・まだ変更していない部位は維持します。JPEGの背景は不透明な元画像として扱います。陰影を残したい箇所は別部位または未割り当てにしてください。
- 部位別カラーと従来の「全体を1色で着色」は併用しません。部位を設定した素材は元画像から部位ごとに着色します。
- 設定は素材ID＋リビジョンと部位IDで保存されます。部位追加後も、旧リビジョンの素材や保存済みユニフォームは変わりません。ユーザーが新しいバージョンを選び直すと新しい部位を利用できます。素材を切り替えた面の部位カラーはリセットします。

部位名・基準色・サイズの要約だけをD1の既存メタデータへ追加し、画素マップは既存KVの非公開原稿用オブジェクトに保存します。図形原稿もある場合は同じオブジェクトに同梱し、合計2MiBまでです。認証付きの `GET /api/uniform-assets/:id/versions/:revision/regions` は公開済みバージョンの部位マップのみを返し、非公開の図形原稿は返しません。下書きは有効な管理者セッションが必要です。未反映のマップは画像同様に503として再確認します。追加DBマイグレーションは不要です。

### 服本体の作成を依頼する場合

「モデル定義」は、シャツの外形・袖・襟・縫い目を正面／背面のSVG座標で表す服本体の設計データです。「モデルJSONを読み込む」はその設計データの取り込みであり、柄・エンブレムの画像や図形原稿JSONとは別です。標準モデルを使うだけなら操作不要ですが、将来新しい服の形を追加するために必要な上級者向け機能として残しています。部位別カラーにもモデルJSONの編集は不要です。

まず標準モデルをコピーして「モデル定義を書き出す」で取得したJSONを元に制作してください。

- 形式: `physiproof-uniform-model`、version: `1`、view_box: `0 0 600 640`。
- 正面 `front`、背面 `back` の各SVGパス: `outer`（外形）、`body`（身頃）、`sleeveSeam`、`sideSeam`、`hem`、`cuff`、`cuffSeam`。
- `outer` と `body` は既定の襟開口へ接続するパスです。標準モデルの端点構造を維持するか、`neckline` で外形を閉じる末尾パスを指定してください。
- 任意: `collar`（襟の閉じたパス）、`cavity`（首元の奥の閉じたパス）。省略すると標準の首元を使用します。
- SVG文書そのものやHTML、JavaScript、外部URLは受け付けません。パスは数値とSVGパス命令のみ、各20,000文字、JSON全体100KB以内です。
- 布地・しわの陰影は600×640の標準的な半袖ユニフォーム用です。異なる大きさ・形（パンツ、立体モデル等）には別レンダラーが必要です。

SVG柄はブラウザで安全な要素に検査してPNGへ変換します。実行コード、外部参照、アニメーション等は取り込めません。ブランドの商標・特徴的なデザインは許諾を確認し、権利のある素材のみ登録してください。

## 保存と安全上限

素材のID＋リビジョンをデザインに保存します。更新は追加保存で、旧リビジョンの内容は変更・削除しません。競合時は409を返し、フォームの下書きを残します。最新の設定を確認してから再編集してください。

- 元画像: 15MiB以内。変換後PNG: 4MiB以内。
- 柄: 縦横2048px、エンブレム: 縦横1024px以内。
- サムネイル: 縦横256px／128KiB以内（通常192pxで生成）。
- 図形原稿: 2MiB以内、100レイヤー、合計20,000点以内。
- 素材ライブラリ: 900MB（900,000,000 bytes）、1日900オブジェクト書き込み、1日300バージョンの安全上限。通常は画像＋サムネイルの2書込、部位マップまたは図形原稿付きは3書込です。両方あっても3書込のままです。回数はUTC 00:00＝日本時間9時にリセットします。
- D1で保存前に容量・回数を原子的に予約するため、同時登録でも上限を越えません。保存失敗・通信断・競合時の予約は、応答不明の実書込を過小評価しないため容量・当日の回数とも保守的に保持します。容量表示は処理中・失敗した予約分を含みます。不要な予約の精査・解放は別途保守作業です。成功分は二重計上しません。
- この保護は本アプリの素材アップロードのみが対象です。他用途のKV使用量、読取回数、D1/Workersの制限を全体管理するものではありません。
- D1: カタログ・モデル定義・部位要約・参照・リビジョン・保存予約。Workers KV: PNG・サムネイル・図形原稿／部位マップ。カタログ一覧に画像本体・画素マップは含めません。

## カード登録不要のKV接続

WorkerのKVバインディング名は `UNIFORM_ASSETS_KV`、専用名前空間は `my-app-backend-UNIFORM_ASSETS_KV` です。2026-10-16にカード登録やプラン変更なしで作成しました。設定は `packages/backend/wrangler.toml` の `[[kv_namespaces]]` にあります。認証トークンをチャットやGitに貼り付けないでください。

未接続でもモデル定義の追加・保存は可能ですが、画像の新規登録は503で止め、管理者画面にも未接続を表示します。GitHub ActionsのデプロイトークンにもKVバインディングを設定する権限が必要です。

KVは結果整合性のため、画像が他の拠点へ反映されるまで60秒以上かかる場合があります。登録元は成功した画像をメモリで即時プレビューし、再読込した端末は保存先から取得します。保存済みバージョンの画像が未反映の場合は503＋`Retry-After: 30`＋`Cache-Control: no-store`を返し、画面は30秒間隔・最大2回で再確認します。その後は手動で「再読込」してください。未知のバージョンや公開されていない下書きは404のままです。

公式の[KV料金・無料枠](https://developers.cloudflare.com/kv/platform/pricing/)と[結果整合性](https://developers.cloudflare.com/kv/concepts/how-kv-works/)も参照してください。Freeプランでプロバイダー上限に達した場合は操作エラーとなります。本作業では有料プラン変更、R2契約、カード登録を行いません。

R2互換アダプター（任意の `UNIFORM_ASSETS`）は残していますが、本番では未接続です。旧R2キーはR2、新しいKVキーはKVへ振り分け、過去の参照を別サービスへ誤転送しません。R2を有効にする必要はありません。

## 管理者セッションと既存認証の注意

素材管理は、ID指定だけの既存簡易認証に加え、管理者がパスワードログインしたときだけ発行される12時間のセッションを必要とします。保存するのはトークンのSHA-256ハッシュです。再ログインで旧セッションは失効し、期限切れや管理者権限剥奪も確認します。デプロイ後は管理者として再ログインしてください。

これは新しい素材管理を保護する追加措置であり、既存システム全体の認証改修ではありません。既存APIはテスト用トークン／署名未検証JWTを許可し、既存パスワード保存も未ハッシュのままです。本格公開に向けて、これらとログイン試行制限を別途改善する必要があります。

通常の動作確認は、プロジェクト直下で `npm run dev` を実行し、`http://127.0.0.1:5173/admin?tab=uniform-templates` を開いてください。このルートは本番と同じ `AdminDashboard`、素材ライブラリ、完成品テンプレートを使います。ローカルDBの未適用更新は起動前に適用されます。本番のデータ・画像・ログイン状態は共有されないため、登録件数や素材が違うこと自体は正常です。ローカルの管理者としてログインする必要があります。

下記の単体テスト画面は、管理メニューを含む通常の管理画面とは異なります。ページの注意枠から通常画面へ移動できます。検証画面を本番と同じに見せるための偽管理者ログインや、本番APIへの付け替えは行いません。
