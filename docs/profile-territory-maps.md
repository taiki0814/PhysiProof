# 年代・フレンド・プロフィール領域マップ

## 利用者向け仕様

- 新規登録で年齢（1〜120の整数）を入力。既存利用者はプロフィール設定で入力・更新できる。生年月日は収集せず、年齢の自動加齢はしない。
- 通常の個人マップは「全員／マイエリア／フレンド」と年代で絞り込める。フレンドは自分と相互承認済みのフレンド。未設定の旧アカウントは「未設定」。具体的な年齢は公開APIに含めない。
- ホームの「自分の領域・履歴を見る」、プロフィール設定の同名ボタン、フレンド一覧の「領域マップ」から閲覧。
- プロフィールの地図は初期状態で「非公開（自分だけ）」。本人が「フレンドに公開」を選ぶと、現在の領域と取得履歴を相互フレンドだけに公開する。チームメンバーや管理者という理由だけでは閲覧できない。
- **この非公開設定は通常の「全員」マップには適用されない。** 現在の領域・所有者は引き続き通常マップに表示される。住所推測やフレンドによる画面保存を完全に防ぐ仕組みではない。
- プロフィール地図の対象は個人活動の領域。チーム・対戦専用領域、走行軌跡、取得時刻・住所一覧は含めない。ゲーム上の所有権や得点は表示の絞り込みで変わらない。
- 「これまでの領域」は重複しうる取得範囲の表示であり、合計面積ランキングではない。導入時の現在保有分を旧データとして引き継ぎ、その後の個人取得を保存。導入前に失った領域は復元不能。

## API・保存

- `POST /api/auth/signup`: `loginId,password,name,age`。初期公開範囲はprivate。
- `POST /api/auth/login`: 正しいパスワードで14日有効の`accessToken`を発行。保護APIの`Authorization: Bearer <accessToken>`に使用する。パスワード・ハッシュは返さない。
- `POST /api/auth/logout`: 現在のセッションを失効。
- `PUT /api/users/me`: 既存項目に加え`age`と`territory_map_visibility: private|friends`。現在の本人だけ更新可能。
- `GET /api/territories?scope=all|mine|friends&age_band=10`: 具体年齢を除き`age_band`を返す。allは引き続き公開、mine/friendsは認証必須。年代表現はunder10、10〜90（10刻み）、100+、unknown。URLの100+はURLエンコードする。
- `GET /api/profiles/:id/territory-map?mode=current|history&before=...`: 本人か、公開許可のある相互フレンドのみ。401はログイン切れ、403は公開権限なし。最大100件、`next_before`で続きを取得。ページごとに権限再検証。現在領域はオフセット、履歴は不変の整数IDによるキーセット。
- 0037は加算的移行。`personal_territory_history`に現在の個人領域をスナップショットし、以後は走行領域の確定バッチ内で個人取得形状を追加。失敗・二重送信では履歴も領域も増えない。対戦ロジックは変更しない。

## 本人確認と互換性

- 従来の任意UID付きtest-tokenと署名未検証JWTを本番認証には使わない。セッションのランダム値はSHA-256ハッシュのみD1に保存し、有効期限とユーザーの存在を検証する。
- 旧平文パスワードはログイン成功時にPBKDF2-SHA256へ移行。新規・変更時もハッシュ保存する。パスワード変更時は他の通常セッションと素材管理用の追加証明を失効する。管理者によるパスワードの閲覧機能は廃止。
- 素材管理の既存12時間追加証明は維持する。今回の反映後、通常の再ログインが必要。古いタブには別タブ再ログインの案内を表示し、無条件の画面遷移で編集中素材を捨てない。
- 合成UIDのバイパスは`AUTH_TEST_MODE=isolated-fixture`を明示する隔離テストだけ。Wrangler/本番設定には一切追加しない。新機能の統合テストと実workerd保存検証は本物のパスワード発行セッションを使用する。
- Android試作クライアントのFirebase IDトークンは従来から署名検証が未完成だった。今後接続する場合、このログインAPIのセッション方式へ対応させるか、別途厳密なFirebase署名検証を実装する必要がある。今回の検証対象はWeb版。

## 軽量化・プライバシーの限界

- 領域・取得履歴・得点はD1を正本とし、端末の削除・改ざん・他端末利用で所有権が変わらない。
- 端末には公開の全員マップだけを最大約2MB（UTF-16文字列上限による概算）、5分間のキャッシュとして保持。通常取得はETagでD1の軽量リビジョンを確認し、変更なしなら全領域の再取得を省く。容量制限・保存無効時も動作する。
- キャッシュを読むだけのオフラインモードは提供しない。サーバーの304確認後だけ再利用し、オフラインの走行・後送は従来どおり禁止。
- プロフィール・フレンド限定応答は`private, no-store`、永続端末キャッシュなし。開いている他人のプロフィールは30秒ごと・フォーカス復帰時に公開権限を再確認し、拒否／通信失敗時には形状を消す。別タブのセッション変更時も再検証する。
- 既に画面に表示された情報の完全な回収はできない。通常マップ自体を隠す機能や自宅付近のぼかしは今回の仕様に含まない。

## 運用・戻し方

既存のGitHub ActionsでD1移行→Worker→Pagesの順に反映する。新しい有料サービス・APIキーは不要。データ移行やパスワードハッシュ化を元に戻してはならない。地図UIを戻す場合も、この認証・ハッシュ対応は残すこと。単純に変更前の認証コードへ戻すと、移行済みパスワードでログインできず、以前の認証の弱点も復活する。

`/qa/profile-map.html`は開発専用の架空・メモリ内UI。API呼び出しを全てそのページ内で遮断し、実DB・認証を使わない。本番ビルドのエントリには含めない。認証・認可の証明は別の実SQLite統合テストで実施する。
